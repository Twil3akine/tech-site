E0502 は共有参照で借用している値を、同じ期間に可変参照で借用しようとしたときに発生するコンパイルエラーである。エラーコードの説明は[公式ドキュメント](https://doc.rust-lang.org/error_codes/E0502.html)で確認できる。

これはコンパイルエラーになる。

```rust
fn main() {
    let mut values = vec![1, 2, 3];
    let first = &values[0];

    values.push(4);

    println!("{first}");
}
```

## エラー文を読む

コンパイラは概ね次のような診断を出す。

```text
error[E0502]: cannot borrow `values` as mutable because it is also borrowed as immutable
 --> src/main.rs:5:5
  |
2 |     let mut values = vec![1, 2, 3];
  |         ---------- help: consider changing this to be a mutable binding: `let mut values`
3 |     let first = &values[0];
  |                  ------- immutable borrow occurs here
5 |     values.push(4);
  |     ^^^^^^^^^^^^ mutable borrow occurs here
6 |
7 |     println!("{first}");
  |              ------- immutable borrow later used here
```

実際の表示はコードやバージョンで少し変わる。確認すべき点は、`first` を作った共有借用が `push` のあとも `println!` で使われていることである。`push` は Vec の要素を追加するため可変借用を必要とし、共有借用が残っている期間には許可されない。

## なぜ起きるか

Rust では、ある値について次のどちらか一方だけを許可する。

- 共有参照 `&T` は複数作れる
- 可変参照 `&mut T` は1つだけ作れる

この決まりにより、値の変更中に古い参照から読み出す事故を防ぐ。とくに Vec の `push` は容量が不足すると内部の保存領域を取り替えることがあるため、要素への古い参照を残したまま実行できない。

現在の Rust の借用検査は NLL（Non-Lexical Lifetimes）を使い、参照の寿命をブロックの終わりではなく、最後に使われる場所までで判断する。そのため、共有参照を使い終えてから変更するコードはコンパイルできる。

## 直し方1: 借用を使い終えてから変更する

参照で読みたい処理を先に終え、そのあとで値を変更する。

```rust
fn main() {
    let mut values = vec![1, 2, 3];
    let first = &values[0];

    // first の利用はここで終わる
    println!("{first}");

    values.push(4);
    assert_eq!(values, vec![1, 2, 3, 4]);
}
```

順序を入れ替えるだけで直る場合は、参照を長く保持する必要がなかったということである。借用の範囲を短く保つことが基本になる。

## 直し方2: 必要な値だけをコピーする

あとで元の値を変更する一方、要素の値そのものは保持したい場合は、参照ではなく値をコピーして持つ。要素が `Copy` を実装する型なら代入でコピーできる。

```rust
fn main() {
    let mut values = vec![1, 2, 3];
    let first = values[0];

    values.push(4);

    assert_eq!(first, 1);
    assert_eq!(values, vec![1, 2, 3, 4]);
}
```

String などの値を保持したい場合は `clone` を使う。コピーや複製のコストがあるため、参照の利用範囲を分けられる場合は、そちらを優先する。

## 直し方3: 借用の範囲をブロックで分ける

計算中だけ参照が必要な場合は、ブロックの中で参照を作り、結果だけを外へ持ち出す。

```rust
fn main() {
    let mut values = vec![1, 2, 3];

    let doubled_first = {
        let first = &values[0];
        *first * 2
    };

    values.push(4);

    assert_eq!(doubled_first, 2);
    assert_eq!(values.len(), 4);
}
```

ブロックを出る時点で `first` は使われなくなるため、そのあとの可変借用と競合しない。

## 直し方4: スライスを分けてから変更する

配列や Vec の別々の範囲を同時に変更したい場合は、`split_at_mut` で可変スライスを2つに分ける。範囲が重ならないことを型で示せるため、両方を可変参照として保持できる。

```rust
fn main() {
    let mut values = [1, 2, 3, 4];
    let (left, right) = values.split_at_mut(2);

    left[0] += 10;
    right[1] += 40;

    assert_eq!(values, [11, 2, 3, 44]);
}
```

ただし、`split_at_mut` は範囲を分けるための方法であり、共有参照と可変参照の競合そのものを回避する手段ではない。読み取り用の参照が残っている場合は、先に利用範囲を終える必要がある。

## 判断の目安

E0502 が出たら、まずエラーの下にある「immutable borrow later used here」がどこを指すかを確認する。その参照が変更前に本当は不要なら利用範囲を短くし、変更後も値が必要ならコピーまたは `clone` を選ぶ。参照同士の範囲が分かれているなら、ブロックや `split_at_mut` で構造を分ける。
