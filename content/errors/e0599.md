E0599 は、値に対して存在しないメソッドを呼ぼうとしたときに発生するコンパイルエラーである。エラーコードの説明は[公式ドキュメント](https://doc.rust-lang.org/error_codes/E0599.html)で確認できる。最初に、ファイルを行ごとに読むコードでこのエラーになる例を示す。

これはコンパイルエラーになる。

```rust
use std::fs::File;
use std::io::BufReader;

fn main() {
    std::fs::write("lines.txt", "one\ntwo\n").unwrap();

    let file = File::open("lines.txt").unwrap();
    let reader = BufReader::new(file);

    let lines: Vec<String> = reader.lines().collect::<Result<_, _>>().unwrap();
    assert_eq!(lines.len(), 2);
}
```

## エラー文を読む

コンパイラは概ね次のような診断を出す。実際の行番号や補足表示は Rust のバージョンや出力設定で異なるが、それぞれの行が示す役割は同じである。

```text
error[E0599]: no method named `lines` found for struct `BufReader<R>` in the current scope
  --> src/main.rs:10:37
   |
10 |     let lines: Vec<String> = reader.lines().collect::<Result<_, _>>().unwrap();
   |                                     ^^^^^ method not found in `BufReader<File>`
   |
   = help: items from traits can only be used if the trait is in scope
help: trait `BufRead` which provides `lines` is implemented but not in scope; perhaps you want to import it
   |
 1 + use std::io::BufRead;
```

注目する点は2つある。1つ目は、`lines` というメソッド自体は `BufReader` に実装されていると診断が示していること。2つ目は、その提供元である `BufRead` トレイトがスコープにないため呼べない、と理由まで書かれていることである。

## なぜ起きるか

Rust のメソッドは、型自身に定義されるものと、トレイトが提供するものの2種類がある。トレイトが提供するメソッドは、そのトレイトを `use` してスコープに入れなければ呼べない。メソッドの実体が存在しても、スコープの外からは見えないためである。

ただし、E0599 になる原因はこれだけではない。メソッドを持つ型とは別の型の値に対して呼んでいる場合や、メソッド名自体を書き間違えている場合も、同じく「メソッドが見つからない」という形で報告される。診断に付く補足が原因ごとに異なるため、切り分けは補足を読むところから始める。

- 「trait ... is implemented but not in scope」とあれば、トレイトがスコープにない
- 「the method ... exists on the type ...」と別の型が示されれば、値の型が違う
- 「there is a method ... with a similar name」とあれば、名前の書き間違い

## 直し方1: トレイトをスコープに入れる

最初の例は `use std::io::BufRead;` を足すだけで直る。`lines` は `BufRead` トレイトのメソッドであり、インポートして初めて `BufReader` に対して呼べるようになる。

```rust
use std::fs::File;
use std::io::{BufRead, BufReader};

fn main() {
    std::fs::write("lines.txt", "one\ntwo\n").unwrap();

    let file = File::open("lines.txt").unwrap();
    let reader = BufReader::new(file);

    let lines: Vec<String> = reader.lines().collect::<Result<_, _>>().unwrap();
    assert_eq!(lines, vec!["one".to_string(), "two".to_string()]);

    std::fs::remove_file("lines.txt").unwrap();
}
```

診断がインポートすべきトレイト名を示してくれる場合は、そのとおりに `use` を追加するのが最短の直し方である。

## 直し方2: 値の型を確認する

メソッドを持つ型そのものではなく、それを包んだ型の値に対して呼ぶと、同じ E0599 になる。次の例では `String` のメソッド `push_str` を `Option<String>` に対して呼んでいる。

これはコンパイルエラーになる。

```rust
fn main() {
    let text: Option<String> = Some(String::from("hello"));
    text.push_str("!");
    println!("{text:?}");
}
```

診断には「the method `push_str` exists on the type `String`」と表示され、メソッドは `Option` ではなく中身の `String` にあることが分かる。直し方は、中身を取り出してから呼ぶ形に変えることである。

```rust
fn main() {
    let text: Option<String> = Some(String::from("hello"));

    // Some のときだけ中身の String を取り出して使う
    let text = text.map(|mut s| {
        s.push_str("!");
        s
    });
    assert_eq!(text, Some("hello!".to_string()));
}
```

`map` のほか、`if let` で分岐したり、`unwrap_or_default` で値を確定させたりする形も取れる。どれを選ぶかは、`None` の場合にどうしたいかで決まる。

## 直し方3: メソッド名を確認する

名前を書き間違えた場合も E0599 になり、診断は似た名前のメソッドを提案する。

これはコンパイルエラーになる。

```rust
fn main() {
    let values = vec![10, 20, 30];
    let count = values.lenght();
    println!("{count}");
}
```

この場合の診断には「there is a method `len` with a similar name」と表示される。提案どおりに直せばよい。

```rust
fn main() {
    let values = vec![10, 20, 30];
    let count = values.len();
    assert_eq!(count, 3);
}
```

似た名前の提案がない場合は、メソッド名だけでなく、そのメソッドが本当にその型にあるかも疑う。公式ドキュメントで型のページを開き、メソッド一覧と、それを提供するトレイトを確認するのが確実である。

E0599 が出たら、まず診断の補足が3原因のどれを示しているかを確認する。トレイトのインポート漏れ、型の取り違え、名前の間違いの順に当たりを付けると、関係のない箇所を触らずに直せる。
