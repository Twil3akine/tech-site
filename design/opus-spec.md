# Twil3akine Rust 攻略サイト リデザイン仕様書

## 1. デザインコンセプト

- Rust で迷うところを「攻略マップ（網羅）」「順路（推奨順）」「逆引き（エラー）」の3本で解いていくサイトにする。
- 頼もしさは装飾ではなく、分母のある進捗表示と迷わない導線で出す。
- 白地・青1色・大きな見出し。コードの暗いパネルだけを強い面として使う。

## 2. カラーパレット

すべて `:root` の CSS 変数に定義し、変数以外で色を書かない。

| 変数 | hex | 役割・使用箇所 |
|---|---|---|
| `--bg` | `#FFFFFF` | ページ背景（全ページ） |
| `--surface` | `#F6F7F9` | 面。マップカード、フッター、記事行のホバー、コールアウト |
| `--surface-2` | `#EEF0F3` | 面のホバー、チップ背景、表の行区切り |
| `--line` | `#E6E8EC` | 枠が必要なとき専用（リンクカード、表、入力欄のフォーカス前）。区切り線には使わない |
| `--text` | `#16181D` | 本文、見出し |
| `--text-sub` | `#4B5563` | リード文、説明文 |
| `--text-muted` | `#6B7280` | メタ情報、プレースホルダ（白地でコントラスト 4.8:1） |
| `--accent` | `#2563EB` | 唯一のアクセント。リンク、主ボタン、進捗バー、フォーカス、アイコン |
| `--accent-hover` | `#1D4ED8` | 主ボタンとリンクのホバー |
| `--accent-weak` | `#EFF4FF` | 順路番号の背景、「ポイント」コールアウト |

- **アクセントを青にする理由**: 却下された銅色・オレンジ系と色相を離すため。書き手アバターの青髪ともつながる。
- **セクション色は設けない。** 3セクションの区別はアイコンとラベル文字で付ける。
- **意味色は1つだけ。** コンパイラのエラー出力に出る `error[E…]` の行にだけ `#F97066` を使う（暗いパネル上の赤）。

**ダークコードパネル**

白一色の原則の例外として、コードブロックとコンパイラ出力に限って許可する。

| 用途 | hex |
|---|---|
| 背景 | `#0F1117` |
| 本文 | `#E6E8EE` |
| 言語ラベル・行番号 | `#7D8590` |
| keyword | `#93B4FF` |
| string | `#9FD8B0` |
| number / 定数 | `#F2C98A` |
| comment | `#7D8590` |
| 型・関数名 | `#E6E8EE`、weight 600 |

トークン色は上の4色までに抑える。Zola のハイライトはクラス出力方式にして、このパレットを CSS 側で定義する。

インラインコードは背景 `--surface-2`、文字 `--text`、角丸 4px、padding `0.1em 0.4em`、枠なし。

## 3. タイポグラフィ

```
--font-sans: "Inter", "Hiragino Sans", "Hiragino Kaku Gothic ProN",
             "Noto Sans JP", "Yu Gothic UI", "Meiryo", sans-serif;
--font-mono: ui-monospace, "SF Mono", "SFMono-Regular", Menlo,
             Consolas, "Liberation Mono", monospace;
```

- Google Fonts は Inter（可変フォント、wght 400–800）の1書体のみ。`display=swap` を付け、`preconnect` を張る。
- 日本語はシステムフォントに任せる。明朝体・丸ゴシック・手書き風は使わない。

| 記事 H1・一覧 H1 | 40 / 30px | 800 | -0.025em | 1.25 |
| H2・トップのブロック見出し | 28 / 24px | 700 | -0.02em | 1.35 |
| H3・カード見出し | 20 / 18px | 700 | -0.01em | 1.5 |
| 記事行タイトル | 17 / 16px | 700 | -0.005em | 1.5 |

## 4. トップページのレイアウト

**共通の値**

- コンテナ: 最大幅 1120px、左右 padding 24px（640px 未満は 20px）
- 余白スケール: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96px
- ブレークポイント: 640px と 960px
- ブロックどうしは上下 96px（SP は 64px）の余白で区切る。罫線は入れない。

### 4-1. ヘッダー（全ページ共通）

- 高さ 64px、`position: sticky; top: 0`。
- 背景は `rgba(255,255,255,.85)` に `backdrop-filter: blur(8px)`。下線は入れない。
- 8px 以上スクロールしたら `--shadow-sm` を付ける（JS で class 付与。JS がなければ影なしのまま）。
- 左: ワードマーク「Twil3akine」（Inter 18px／800／-0.02em）。その右に「Rust 攻略」を 13px／500／`--text-muted` で並べる。
- 中央〜右: ナビ「標準ライブラリ」「クレート」「エラー解決」（14px／500／`--text-sub`）。項目間は 24px。ホバー時は `--text`、現在のセクションは `--accent`。
- 右端: 検索窓（6章）。
- 960px 未満: ナビを隠す。セクションへの導線はマップとフッターが受け持つ。
- 640px 未満: 検索窓を 40px のアイコンボタンにする。押すとヘッダー直下に全幅の検索行（高さ 56px）が開き、自動でフォーカスが入る。
- 書籍レビューへのリンクは置かない。

### 4-2. ヒーロー

- padding は上 96／下 64px（SP は 56／40px）。背景は白、装飾なし。
- 960px 以上は2カラム（左 7fr／右 5fr、gap 48px）。それ未満は1カラムで、右カラムは表示しない。
- 左カラムに置くもの:
  - H1「Rust を、1テーマずつ攻略する。」
  - リード（最大幅 560px）:「つまずきやすい標準ライブラリ・クレート・エラーを、1記事1テーマで解く日本語の攻略サイト。」
  - ボタン2つ（上 32px、間 12px）: 主「はじめての順路から読む」→ 順路の1本目、副「エラーから探す」→ エラー解決セクション
- 右カラム: ダークパネルを1枚。角丸 16px、padding 24px、`--shadow-md`。中身は E0382（借用後の値使用）のコンパイラ出力を6行ほど載せた静的な HTML。パネルの下に 13px／`--text-muted` で「この直し方 → 記事へ」のリンクを置く。
- 看板「私たちの完全 Rust 攻略サイト」の扱い: 公開数が予定数の 80% に届くまでは H1 に使わず、`<title>` とフッターの説明文に限る。80% を超えたら H1 をこの看板に差し替える（7章）。
- アバターはヒーローに使わない。キャラクターが前に出ると個人ブログに見えるため。使うのは記事の署名とフッターに限る。

### 4-3. 攻略マップ（セクション導線）

- ブロック見出し「攻略マップ」（H2）。右側にメタ「3 エリア・公開 4 本／予定 N 本」（13px／`--text-muted`）。
- グリッド: 960px 以上は3列（gap 24px）、それ未満は1列（gap 16px）。
- カードの仕様（6章「マップカード」）。上から順に:
  1. アイコン 24px（線画、`--accent`）
  2. セクション名（H3、上 16px）
  3. 説明1行（14px／`--text-sub`）
  4. 進捗（上 20px）:「公開 2／予定 12」（13px、数字は `--text` で 700）と進捗バー。バーは高さ 4px、角丸 2px、地は `--surface-2`、塗りは `--accent`。
  5. テーマチップ（上 16px、gap 6px で折り返し）: 公開済みを先に並べ、合わせて最大6個。残りは「ほか N」。
- カード全体ではなく、セクション名をリンクにする。チップはそれぞれ単独のリンクにする。
- エラー解決カードのチップは「E0382」のようにエラーコードで見せる。

### 4-4. はじめての順路（推奨順）

- H2「はじめての順路」。サブ文「上から読めば基礎がそろう」（14px／`--text-sub`）。
- 縦の番号付きリスト（`<ol>`）。最大幅 720px、各行の間は 4px。
- 各行は記事行（6章）の変形で、左端に番号バッジを付ける（32px の円、`--accent-weak` 地に `--accent` の文字、14px／700）。
- 公開済みの記事だけを並べる。準備中のものは載せない。

### 4-5. 新着記事（記事リスト）

- H2「新着」。最新8本を記事行で並べる（最大幅 720px）。
- 9本目以降が出るまでは「もっと見る」を出さない。出たあとは各セクション一覧へのリンクを3つ並べる。

### 4-6. サイドバー

トップには置かない。中身が少ない段階でサイドバーを置くと、空いた欄が目立つ。1カラムと内部のグリッドで構成する。

### 4-7. フッター（全ページ共通）

- 背景 `--surface`、padding 上 48／下 32px。
- 960px 以上は2列、それ未満は縦積み。
- 左列: アバター 40px（円）、「Twil3akine」（15px／700）、紹介1行（14px／`--text-sub`）、看板「私たちの完全 Rust 攻略サイト」。
- 右列: 3セクションへのリンク（14px）と RSS（`atom.xml`）。
- 最下段: © 表記（13px／`--text-muted`）。
- 書籍レビューへの導線は置かない（base テンプレートで共通化するため）。

## 5. 記事ページ（page）と一覧ページ（section）

- **ヘッダー**: トップと同じものを使う。
- **カラム**: 1120px 以上は本文 720px と右の目次 220px（gap 64px）。それ未満は本文だけ。
- **記事冒頭**（上から順に）:
  1. パンくず「ホーム / セクション名」（13px／`--text-muted`）
  2. セクションラベル（チップ）
  3. H1（上 12px）
  4. リード（description、上 16px）
  5. メタ行（上 24px）: アバター 24px、更新日、読了目安（Zola の `reading_time`）、対象バージョン「Rust 1.xx」。項目間は 16px、13px。
  6. 本文開始まで 48px。
- **本文**: 段落の下 20px。リンクは `--accent` に下線（`text-underline-offset: 3px`、太さ 1px）、ホバーで `--accent-hover`。
- **見出し**:
  - H2 は上 64／下 16px、H3 は上 40／下 12px。
  - ホバー時、見出しの左に `#` アンカーを `--accent` で出す（`margin-left: -1.2em`）。
  - `scroll-margin-top: 88px`。
- **目次**:
  - PC は `position: sticky; top: 96px`。H2 だけを並べる（14px／`--text-sub`、行間 1.6、項目間 8px）。
  - 現在位置は `--accent` で 600 にし、左に幅 2px の青いバーを出す（IntersectionObserver を使う）。
  - 1120px 未満は冒頭に `<details>` で置く。背景 `--surface`、角丸 12px、padding 16px 20px、初期状態は閉じる。
- **コードブロック**:
  - ダークパネル、角丸 12px、padding 20px 24px、上下 margin 24px、`overflow-x: auto`。
  - 右上に言語ラベル（12px／`#7D8590`）とコピーボタン（28px 角、角丸 8px）。ボタンは透明地で、ホバー時に `rgba(255,255,255,.08)`。
  - 640px 未満は左右 −20px で画面端まで広げ、角丸 0 にする。
  - ファイル名を見せる場合は、パネル内の最上段に 12px／`#7D8590` のキャプションとして入れる。
- **コールアウト**:
  - 標準: `--surface` 地、角丸 12px、padding 16px 20px、左に 18px のアイコン。
  - 「ポイント」だけ `--accent-weak` 地にする。左の縦線は付けない。
- **表**: 見出し行は `--surface` 地。行の区切りだけ 1px `--surface-2`。外枠は付けない。
- **記事末**（上から順に）:
  1. 「攻略済みにする」ボタン（副ボタン。押すと主ボタンの見た目に変わり「攻略済み ✓」と表示）
  2. 順路の次の記事（リンクカード1枚。見出し「順路の次」）
  3. 関連記事3本（同じセクションの記事を新しい順に。グリッドは 640px 以上で3列）
- **一覧ページ（section）**:
  - H1、説明、進捗（マップカードと同じ表示）、記事行のリスト。
  - 末尾に「準備中のテーマ」として未公開チップを並べる。
  - 本文幅は 720px。

## 6. コンポーネント仕様

**共通トークン**

```
--radius-sm: 8px;  --radius-md: 10px;  --radius-lg: 12px;  --radius-xl: 16px;
--shadow-sm: 0 1px 2px rgba(16,24,40,.06);
--shadow-md: 0 4px 16px rgba(16,24,40,.08);
--shadow-lg: 0 12px 32px rgba(16,24,40,.10);
--ease: 160ms cubic-bezier(.2,.6,.2,1);
```

- フォーカスは全要素で共通: `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }`
- 角丸は要素の値に従う。`outline: none` だけを書いて済ませることは禁止。

| 部品 | 仕様 |
|---|---|
| 主ボタン | 高さ 44px（SP 48px）、padding 0 20px、角丸 10px、`--accent` 地に白文字（15px／600）、影なし。ホバーで `--accent-hover`、押下中は `translateY(1px)` |
| 副ボタン | 寸法は主ボタンと同じ。`--surface-2` 地に `--text`。ホバーで `#E4E7EB` |
| テキストボタン | `--accent` の文字。ホバーで下線 |
| マップカード | `--surface` 地、枠なし、影なし、角丸 16px、padding 28px（SP 24px）。カード自体はリンクにしないので、ホバー効果も付けない |
| リンクカード（順路の次・関連記事） | 白地、`1px solid var(--line)`、角丸 12px、padding 20px、`--shadow-sm`。中身はラベルチップ、タイトル（17px／700）、メタ。ホバーで `--shadow-md`、`translateY(-2px)`、タイトルを `--accent` に（`--ease`） |
| チップ | 高さ 26px、padding 0 10px、角丸 999px、`--surface-2` 地に `--text-sub`（12px／600）。リンクのチップはホバーで `#E4E7EB` 地、`--text`。準備中のチップは背景なしで `--text-muted`。末尾に「準備中」の文字を付け、リンクにしない |
| 記事行 | ブロックリンク。padding 16px、左右 margin −16px（文字の左端をそろえる）、角丸 12px。グリッドは「本文 1fr ／ メタ auto」。本文側はラベルチップ、タイトル（上 6px）、説明（14px／`--text-sub`、1行で省略）。メタは 13px／`--text-muted`。ホバーで `--surface` 地、タイトルを `--accent` に。行どうしの区切り線は付けない。攻略済みの行は、タイトルの前に 16px の ✓（`--accent`）を出す。640px 未満ではメタを説明の下へ回す |
| 検索窓 | 高さ 40px、幅 240px（960px 以上はフォーカス時に 320px へ広げる、200ms）、角丸 10px、`--surface-2` 地、枠は透明。左の虫眼鏡 16px（`--text-muted`）に合わせて padding-left 36px。文字 14px。プレースホルダ「記事を検索（例: Option, E0382）」。右端に「/」キーのヒント（20px 角、角丸 6px、白地、12px）。フォーカス時は白地、`1px solid var(--accent)`、`box-shadow: 0 0 0 3px rgba(37,99,235,.20)` |

**検索の実装**: `<form action="https://www.google.com/search" method="get">` の中に `q` と、hidden の `as_sitesearch`（サイトのドメイン）を置く。JS なしで送信できること。「/」キーでフォーカスする機能は JS による追加で、なくても困らない作りにする。

## 7. 「網羅・攻略」の情報設計

1. **分母を見せる**:
   - 各セクションの `_index.md` の `[extra]` に `planned = ["テーマ名", …]` を持たせる。
   - 表示する数は「公開数（`section.pages | length`）／予定数（公開済み＋planned）」。
   - 少ない記事数をごまかさず、どこまで進んだかを見せることが頼もしさになる。
2. **看板の段階表示**: 「完全」の語は、全体の公開率が 80% に届くまで H1 に出さない（4-2）。判定は `config.extra.show_full_title` を手で切り替える。自動にはしない。
3. **推奨順**:
   - `config.extra.route = ["記事パス", …]` で順路を定義する。トップの順路ブロックと記事末の「順路の次」の両方がこれを参照する。
   - 旧案の「STAGE」表記は「順路 1, 2…」の番号バッジに置き換える。
4. **逆引き**: エラー解決の記事は、タイトルと slug にエラーコードを入れる（例「E0382: borrow of moved value の直し方」）。マップのチップと検索のプレースホルダで、エラーコードから探せることを伝える。
5. **読了管理**: 残す。ただし今どきの控えめな見せ方にする。
   - 保存先は localStorage のみ。ログインはしない。
   - 記事末の「攻略済みにする」で記録し、記事行の ✓ とマップカードの「あなた 2／4」に反映する。
   - 1件も記録がないうちは個人の進捗表示を出さない。
   - JS がない環境ではボタンごと非表示にする。
6. **難易度表示**: 捨てる。記事が4本しかない段階では、ドットで難易度を付けても比べる相手がない。易しい順は順路が示す。

## 8. 現行案から捨てるもの

- 紙色の背景 `#FAF6EF`、方眼などのテクスチャ全般
- 銅色と茶系の補助色
- セクションごとの色3色。アクセントは青の1色にまとめる
- 全要素に付いた 1px の実線枠
- 6px 以下の角丸と実線枠の組み合わせ（インラインコードと kbd は例外）
- オフセット付きのハードシャドウ（`3px 3px 0` の類）すべて
- 罫線による区切り、見出しの下線や飾り記号
- 難易度ドット
- 「STAGE」表記（順路の番号に置き換え）
- 情報を詰め込んだ第一画面
- サンセリフ以外の書体と、Google Fonts の2書体目
- トップ・ヘッダー・フッターからの書籍レビュー導線

## 9. 実装チェックリスト

1. CSS の中で hex 値が出てくるのは `:root` の変数定義だけになっている（grep で確認）。
2. `box-shadow` に、ぼかしが 0 でオフセットだけの値が1つもない。
3. `border-radius` の値が 4／6／8／10／12／16／999px のどれかに収まっている。
4. 1440×900 と 375×812 の第一画面に見えるのは、H1・リード・ボタン2つだけ（PC ではそれに右のパネル1枚）。
5. 本文・メタ・ボタン文字のコントラストが 4.5:1 以上ある（`--text-muted` を白地に置いた場合も含む）。
6. Tab キーだけで、ヘッダー、検索、ボタン、記事行、目次、コピーボタンを順に移動でき、どこでもフォーカス枠が見える。
7. ビルド後の `public/index.html` に書籍レビューへのリンクがない。
8. JS を切った状態で、検索の送信（サイト内に限定されている）、レイアウト、目次の `<details>` が動く。読了の UI は出ない。
9. 320px 幅で横スクロールが出ない（コードブロックの中だけは例外）。
